# Realman MCAP 本地质检：使用说明

这套入口现在可以检查真实 MCAP，并生成中文 HTML 报告和机器可读 JSON。它是采集数据进入后续处理前的技术预检，不判断任务是否成功，也不做子任务划分。

## 直接开始

1. 双击项目根目录的 `启动HFlow质检.cmd`。
2. 程序检查 `HFlow/data/inputs/` 当前目录下所有 `.mcap`。这里已放入两份获准使用的样本副本。
3. 等待完成，默认浏览器会打开本次中文报告。命令窗口保留结果，按任意键关闭。

也可以把一个 MCAP 文件或一个文件夹拖到这个 CMD 上，只检查拖入的位置。文件夹模式不递归检查子目录。

输入来自 Windows；程序先复制到 WSL 的独立数据目录，再进行检查。检查前后校验 SHA256，原始文件不修改。重复检查时，哈希相同的缓存副本会复用，但质检重新执行。

新文件放入 `data/inputs/` 即可。当前配置适用于这两份样本的 Realman topic 和 ROS2 消息格式；其他机器人应先修改配置，不能把“缺少本配置的必需 topic”直接解释为录制设备坏了。

## 报告怎么看

报告在 `HFlow/data/quality-reports/<本次时间>/`：

| 文件            | 用途                                           |
| --------------- | ---------------------------------------------- |
| `report.html` | 双击查看中文结果、各路统计、问题定位和完整证据 |
| `report.json` | 完整结构化证据，方便后续接入其他系统           |
| `config.json` | 本次实际生效的配置快照                         |

`data/quality-reports/latest-report.txt` 记录最新报告路径。每次运行保留独立报告，不覆盖以前的记录。

| 结果                | 含义                                               | 建议                           |
| ------------------- | -------------------------------------------------- | ------------------------------ |
| PASS / 技术检查通过 | 当前配置内的检查全部完成且未发现需复核项           | 仅表示技术检查通过             |
| REVIEW / 需要复核   | 出现静止、采样缺口、同步偏差等线索，或配置尚未校准 | 打开问题定位，结合原始录像确认 |
| FAIL / 发现明确问题 | 例如文件不完整、必需数据流缺失、解码失败、NaN/Inf  | 暂不作为合格数据放行           |
| ERROR / 检查未完成  | 环境、执行或输入变化等问题导致检查不完整           | 修复后重新运行                 |

退出码 `0` 表示 PASS；`2` 表示质检已完成但有 REVIEW/FAIL；`3` 表示执行失败。退出码 2 不是程序启动失败。

当前配置 `calibrated=false`，因此即使没有其他异常也会提示复核。公司确认必需数据流、频率、同步容差等验收规则后，再决定是否启用自动通过。不要只为了看到 PASS 而修改这个开关。

## 实际检查什么

| 项目           | 当前实现                                                                                                       | 需要注意                                                    |
| -------------- | -------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 文件完整性     | 检查 MCAP 首尾标识、DataEnd/Footer，顺序读取完整记录，验证库支持的非零 chunk/data CRC                          | CRC 为零表示未提供校验；不保证所有索引语义都正确            |
| 缺少数据流     | 检查左头、左臂、右臂三个相机及左右从臂状态是否存在且有消息                                                     | 规则放在配置文件                                            |
| 图像可读性     | 对所有读出的 ROS2 CompressedImage 逐帧解码，检查 JPEG 结束标记，允许末尾零填充                                 | 不需要先转成 MP4，不调用付费模型                            |
| 黑帧           | 原尺寸灰度画面中，灰度不高于 16 的像素达到 98% 时提示                                                          | 只要求人工复核                                              |
| 静止画面       | 缩小为 160×90 后，相邻画面平均灰度差不高于 0.5，连续至少 2 秒时提示                                           | 正常等待也会触发；缺帧不能累计为静止                        |
| 清晰度线索     | 缩小画面的拉普拉斯方差低于 30，且超过半数帧时提示                                                              | 低纹理场景也会触发，不等于画面一定模糊                      |
| 时间连续性     | 记录时间重复、倒退、较长间隔；检查解码消息的 header 时间                                                       | 原始记录顺序保留，不先排序掩盖异常                          |
| 同步线索       | 每个必需相机帧与两路从臂状态最近采样时间差，超过 50 ms 时提示                                                  | 使用 MCAP log_time，不证明硬件同步精度                      |
| 机器人状态     | 解码嵌套 `joint_state.position`，检查空数组、长度变化、NaN/Inf；可选检查速度、力矩、加速度、夹爪数值是否有限 | 当前只检查配置中的左右从臂；单位未确认，不判速度/加速度超限 |
| HFlow 内置检查 | 对完整文件运行 `required_topics` 和 `timestamp_regularity`，保存原生结果                                   | 不完整文件跳过并说明原因，不伪造成功结果                    |

没有配置固定帧率时，时间缺口相对于该路数据的正时间间隔中位数判断，超过 3 倍才提示。这样可以适配不同频率的相机，但无法发现“整段始终低于应有采样率”的问题。待确认设备额定频率后，可填写 `expected_hz`。

事件类 topic 仅统计时间和数量，不按周期采样规则判缺帧。其他未适配消息内容明确标记为 `not_in_profile`，不会声称已检查所有字段。

默认不检查主臂动作、body 内容、策略输出的动作格式、相机标定、任务成功率、动作合理性、遮挡或目标是否在视野中。静止和清晰度是图像统计，不是 VLM 语义判断。

## 首次两份真实样本的结果

2026-10-20 完成实际扫描：

| 样本                | 结果   | 主要发现                                                                                                                   |
| ------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------- |
| Cooking，约 498 MiB | REVIEW | 文件完整；读到 54,902 条消息；9 路相机均可解码；左右从臂状态可解码；部分静止段和状态采样间隔需复核                         |
| rollout，约 420 MiB | FAIL   | 缺少正常文件尾部，扫描在 EOF 结束；只能检查可读前缀，读到 37,717 条消息；另有设备时间戳重复、采样缺口和相机/状态时间差线索 |

Cooking 的可读记录跨度约 34.10 秒；rollout 可读记录跨度约 228.13 秒。这个跨度使用所有已读消息的最早/最晚记录时间，不等于单个相机视频时长。

rollout 可读前缀的 4 路图像本次均可解码；左右从臂状态同样可解码。文件不完整仍然是独立问题，不能因为前面画面可看就验收通过，也无法仅凭这个文件判断末尾究竟丢失了多少帧。

本机单份扫描约十几秒，包含逐帧解码及检查前后哈希；整个启动流程还包括输入复制和其他哈希校验。耗时取决于文件大小、硬盘与 CPU，不能当成速度承诺。

## 配置和代码放在哪里

| 位置                                                                                     | 内容                                                          |
| ---------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `configs/realman-qc.json`                                                              | 必需 topic、机器人状态字段、频率和质检阈值                    |
| `src/hflow/realman_qc.py`                                                              | Realman 原始数据适配、HFlow 调用、报告和批处理                |
| `scripts/wsl/quality-check.ps1`                                                        | Windows 质检启动与报告打开                                    |
| `scripts/wsl/run.sh`                                                                   | 同步 Windows 代码到 WSL、使用已配置环境运行                   |
| `tests/test_realman_qc.py`                                                             | 正常、截断、CRC 损坏、图像损坏、NaN、时序、同步和报告回归测试 |
| `data/inputs/`                                                                         | Windows 输入文件；不纳入 Git                                  |
| `data/quality-reports/`                                                                | 每次报告；不纳入 Git                                          |
| `/home/carlosgao/workspaces/ai_Quality_Inspection_Division/HFlow/data/quality/inputs/` | 按哈希保存的 WSL 运行副本                                     |
| `/home/carlosgao/workspaces/ai_Quality_Inspection_Division/HFlow/logs/`                | WSL 执行日志                                                  |

Windows 项目文件为源文件，WSL 的 `repo/` 是运行镜像。请在 Windows 项目中修改代码和配置，下一次启动会同步，避免只修改镜像后被覆盖。

技术人员可以在项目目录运行：

```powershell
.\scripts\wsl\quality-check.ps1 -InputPath 'D:\你的数据目录' -NoOpen
.\scripts\wsl\hflow.ps1 -Action check
.\scripts\wsl\hflow.ps1 -Action run -CommandArgs @('pytest', 'tests/test_realman_qc.py', '-q')
```

此适配没有改动 HFlow 核心转换逻辑、原数采平台或 Argus 代码，没有添加模型 API、GPU 或 Docker 依赖。环境基础说明见 [WSL 环境说明](./local-wsl-setup.md)。
